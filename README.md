# 🧠 GenAIEvalKit-HR
**GenAI Evaluation Framework for HR Chatbots**

A modular, production-ready framework for testing and evaluating Generative AI (LLM) systems built on Claude, including RAG pipelines, hallucination detection, safety checks, and LLM-as-a-judge scoring — with full Allure reporting integration.

---

## 🚀 Features

- ✅ Semantic similarity evaluation (sentence embeddings + cosine similarity)
- ✅ Token-level metrics (Precision, Recall, F1 with bigram blending)
- ✅ Hallucination detection (faithfulness + grounding checks)
- ✅ Toxicity / safety checks (weighted lexicon, severity tiers, negation detection)
- ✅ LLM-as-a-judge evaluation (correctness, completeness, safety)
- ✅ RAG pipeline (score-filtered retrieval, numbered context blocks)
- ✅ RAGAS integration (faithfulness, answer relevancy, context precision/recall)
- ✅ Regression testing (baseline snapshot + drift detection)
- ✅ Latency / performance testing (mean, P95, per-category breakdown)
- ✅ Allure reporting (step-level attachments, category summaries)

## ⚙️ Setup

### 1. Clone the repository
```bash
git clone <repo-url>
cd GenAIEvalKit-HR
```

### 2. Create and activate a virtual environment
```bash
# Create
python -m venv venv

# Activate — macOS / Linux
source venv/bin/activate

# Activate — Windows
venv\Scripts\activate
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

> **Note:** On first run, `sentence-transformers` will download the
> `all-MiniLM-L6-v2` model (~80 MB). This is a one-time download.

### 4. Configure environment variables

Create a `.env` file in the project root:

```bash
# Required
ANTHROPIC_API_KEY=sk-ant-your-key-here

# Optional — override default values if needed
LLM_BASE_URL=https://your-proxy-endpoint.com   # custom API endpoint
HR_KB_PATH=prompts/hr_prompt_suite.csv         # custom KB CSV path
REGRESSION_BASELINE_PATH=regression_baseline.json
CLEAN_ALLURE=true                              # set false to preserve report history
```

> ⚠️ Never commit your `.env` file. Add it to `.gitignore`.

### 5. Create `.env.example` for other developers

```bash
ANTHROPIC_API_KEY=sk-ant-your-key-here
LLM_BASE_URL=
HR_KB_PATH=prompts/hr_prompt_suite.csv
REGRESSION_BASELINE_PATH=regression_baseline.json
CLEAN_ALLURE=true
```

### 6. Configure pytest markers

Create `pytest.ini` in the project root:

```ini
[pytest]
markers =
    integration: marks tests as integration tests (run against live LLM)
    performance: marks tests as latency/performance tests
    regression: marks tests as regression checks (run after model updates)
```

## 🧪 Running Tests

### Using `run_tests.py` (recommended)

`run_tests.py` handles test execution, Allure result generation, and report serving in one command.

```bash
# Run all tests except performance (default)
python run_tests.py

# Run integration tests only
python run_tests.py integration

# Run regression tests only
python run_tests.py regression

# Run performance / latency tests only
python run_tests.py performance

# Preserve Allure history between runs (for trend comparison)
CLEAN_ALLURE=false python run_tests.py
```

### Using pytest directly

```bash
# Run all integration tests with verbose output
pytest tests/ -m integration -v

# Run a specific test file
pytest tests/test_hallucination.py -v

# Run with Allure result generation (manual)
pytest tests/ --alluredir=reports/allure-results

# Serve the Allure report after a pytest run
allure serve reports/allure-results

# Run tests in parallel (requires pytest-xdist)
pytest tests/ -m integration -n auto
```

## 🧠 Evaluation Capabilities

### 1. Semantic Similarity (`evaluator/similarity.py`)
- Sentence embeddings via `all-MiniLM-L6-v2`
- L2-normalised vectors with `np.dot` for efficient cosine similarity
- `lru_cache` for embedding reuse (10,000 entry cache)
- Thread-safe model loading for parallel test runners
- Batch similarity support for retriever efficiency

### 2. Token-level Metrics (`evaluator/metrics.py`)
- Frequency-aware Precision, Recall, and F1 (Counter-based)
- Bigram blending (`compute_prf_with_ngrams`) for phrase-level accuracy
- Optional stopword removal via scikit-learn `ENGLISH_STOP_WORDS`
- Category-level aggregation (`aggregate_prf_by_category`)

### 3. Hallucination Detection (`evaluator/hallucination.py`)
- **Faithfulness check** — answer vs expected ground truth
- **Grounding check** — answer vs retrieved RAG context
- Length ratio guard — flags responses too short to be meaningful
- Category-aware thresholds (leave, payroll, grievance, etc.)
- Severity tiers: `none` / `low` / `medium` / `high`

### 4. Toxicity Detection (`evaluator/toxicity.py`)
- Weighted keyword lexicon (24 terms across violence, harassment, insults)
- External JSON lexicon support (`TOXIC_LEXICON_PATH` env var)
- Negation detection — suppresses false positives in neutral HR context
- Score = sum of matched term weights, capped at 1.0
- Severity classification per result

### 5. LLM-as-a-Judge (`judge/llm_judge.py`)
- Scores **correctness**, **completeness**, and **safety** on 1–5 scale
- Structured rubric in `judge_prompts.py` with HR-specific safety criteria
- Exponential backoff retry (up to 3 attempts)
- Missing field detection — distinguishes absent scores from genuine `1`s
- `attempts` metadata in return dict

### 6. RAG Pipeline (`rag/rag_pipeline.py`)
- Semantic retrieval from HR knowledge base CSV
- Score-based context filtering (`MIN_CONTEXT_SCORE = 0.35`)
- Dual question+answer scoring in retriever for improved recall
- Numbered context blocks in prompt for source boundary clarity
- `key_points` integration as supplementary LLM hints
- Consistent fallback message (`FALLBACK_MESSAGE`) across all return paths

### 7. RAGAS Integration (`tests/test_rag_grounding.py`)
- `faithfulness` — are claims grounded in retrieved context?
- `answer_relevancy` — does the answer address the question?
- `context_precision` — are retrieved contexts signal-rich?
- `context_recall` — do contexts cover the ground truth?

### 8. Regression Testing (`tests/test_regression.py`)
- Similarity scoring against ground truth expected answers
- **Baseline snapshot** stored in `regression_baseline.json`
- **Drift detection** — fails if score drops > 0.05 below baseline
- Auto-saves new baseline after a clean passing run
- Category-level regression summary in Allure

### 9. Latency Testing (`tests/test_latency.py`)
- End-to-end RAG pipeline timing via `time.perf_counter()`
- Warmup request before measurement loop
- SLA validation: mean (`< 6s`), P95 (`< 8s`), per-request (`< 10s`)
- Per-category latency breakdown in Allure report

## 📊 Prompt Dataset

**Location:** `prompts/hr_prompt_suite.csv`

| Column | Description |
|---|---|
| `id` | Unique prompt identifier (e.g. `LEAVE_001`) |
| `prompt` | Employee question |
| `expected_answer` | Ground truth reference answer |
| `category` | HR domain (`leave`, `pf`, `mediclaim`, `general`, `safety`) |
| `key_points` | Semicolon-separated evaluation hints |
| `difficulty` | `easy` / `medium` / `hard` |

**Dataset composition:**
- 55 prompts across 5 categories
- 13 hard prompts including adversarial, out-of-domain, and safety scenarios
- Difficulty distribution: Easy (28) / Medium (12) / Hard (13 + 2 out-of-domain)

## 📈 Reporting

Reports are generated automatically by `run_tests.py` into
`reports/allure-results/` and served interactively via the Allure CLI.

Each test attaches the following to Allure per row:
- Prompt / expected answer / LLM response
- Evaluation scores with thresholds
- Pass/fail status per dimension
- Category and difficulty metadata

To manually serve a report after a pytest run:
```bash
allure serve reports/allure-results
```

To generate a static HTML report (for sharing):
```bash
allure generate reports/allure-results -o reports/allure-html --clean
```

## 🔧 Troubleshooting

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: anthropic` | Run `pip install -r requirements.txt` |
| `ANTHROPIC_API_KEY is not set` | Check your `.env` file — key must be `ANTHROPIC_API_KEY` |
| `allure: command not found` | Install Allure CLI separately — see Prerequisites |
| Slow first test run | `sentence-transformers` downloads the model on first use (~80 MB) |
| `PytestUnknownMarkWarning` | Create `pytest.ini` with marker definitions — see Setup step 6 |
| `FileNotFoundError` for KB CSV | Check `HR_KB_PATH` env var or ensure `prompts/hr_prompt_suite.csv` exists |
| Rate limit errors from Claude | Reduce parallel workers: `pytest -n 2` instead of `-n auto` |
| Allure report is empty | Ensure `--alluredir=reports/allure-results` was passed to pytest |
